## Zusammenfassung Der MERGE Generator erstellt Oracle MERGE-Scripts für die Datenmigration zwischen Datenbanken. Ausgehend von einem einzelnen Datensatz (z.B. einer bestimmten Person) werden automatisch alle abhängigen Datensätze über Fremdschlüssel-Beziehungen gefunden und als zusammenhängendes Script ausgegeben.

Typischer Einsatz:
Stammdaten, Konfigurationen oder Testdaten von einer Oracle-Datenbank in eine andere übertragen – inklusive aller Kind-Tabellen, Sequences und FK-Abhängigkeiten. Das erzeugte Script ist sofort lauffähig und idempotent (MERGE: INSERT wenn neu, optional UPDATE wenn vorhanden).

Unterstützte Sonderfälle:
• Composite PKs: Tabellen mit zusammengesetzten Primärschlüsseln werden korrekt erkannt und im MERGE-ON-Abgleich berücksichtigt
• Self-Referencing FKs: Tabellen, die auf sich selbst verweisen (z.B. MANAGER_ID → EMPLOYEE_ID), werden ohne Endlosschleife traversiert
• Mehrere Suchwerte: Gleichzeitige Analyse mehrerer Datensätze – Ergebnisse werden automatisch zusammengeführt
• Sequence-gemappte PKs: Neue IDs per SEQ.NEXTVAL generieren, FK-Spalten in Kind-Tabellen erhalten automatisch die PL/SQL-Variable
• Virtuelle FKs: Fehlende DB-Constraints manuell definieren, werden beim Traversal mit echten FKs kombiniert und automatisch bereinigt wenn sie später als echte Constraints existieren
• Subselect-FK-Mapping: Referenzdaten, die auf der Ziel-DB bereits existieren aber andere IDs haben, werden per Subselect aufgelöst statt mit Literal-Werten eingebettet
• Konstantentabellen: Tabellen, die als Konstantentabellen markiert sind, werden aus dem MERGE-Script gefiltert
• Testmodus: Jeder Lauf erzeugt ein neues Objekt durch Timestamp-Suffix – ideal für wiederholbare Tests ohne manuelle Bereinigung
• Skip-Check: Bei INSERT-only mit Kind-Tabellen wird automatisch geprüft, ob der Root-Datensatz eingefügt wurde – wenn nicht, werden Kind-Inserts übersprungen ## Eingabe Führende Tabelle:
Name der Oracle-Tabelle, von der die Analyse startet. Groß-/Kleinschreibung wird automatisch in Großbuchstaben umgewandelt. Pflichtfeld.

Spaltenname:
Optionale Angabe der Suchspalte. Wenn leer, wird automatisch der Primärschlüssel der Tabelle verwendet. Nützlich, wenn nach einem Namensfeld statt der ID gesucht werden soll.

Werte:
Suchbegriffe – ein Wert pro Zeile. Mehrere Werte werden nacheinander analysiert und die Ergebnisse zusammengeführt. Mindestens ein Wert ist erforderlich.

Testmodus:
Hängt einen Zeitstempel (_yyyyMMddHHmmss) an den Wert der Suchspalte an. Dadurch schlägt der MERGE-Abgleich immer fehl und es wird stets ein neuer Datensatz per INSERT angelegt. Voraussetzung: Spaltenname muss ausgefüllt sein.

Bei Übereinstimmung aktualisieren:
Ergänzt den MERGE um eine WHEN MATCHED THEN UPDATE SET-Klausel für alle Nicht-PK-Spalten. Ohne diese Option wird bei Übereinstimmung nichts getan (INSERT-only). ## Analyse-Verlauf vs. Presets Es gibt zwei unabhängige Mechanismen, um frühere Abfragen wiederzuverwenden:

Analyse-Verlauf (automatisch):
Links neben der Eingabe wird der Verlauf aller bisherigen Analysen automatisch aufgezeichnet (Tabellenname + gekürzte Werte). Jede durchgeführte Analyse wird hier gespeichert – ohne manuelles Zutun.
• Eintrag anklicken: Lädt die Abfrage in die Eingabefelder
• "Entfernen": Löscht den markierten Verlaufseintrag
• Duplikate werden erkannt: gleiche Tabelle + Spalte + Werte aktualisieren nur den Zeitstempel und werden nach vorne verschoben

Query-Presets (manuell):
Über die Preset-Leiste oberhalb der Eingabe können häufig genutzte Abfragen bewusst als benanntes Preset gespeichert werden. Im Gegensatz zum Verlauf werden Presets nur auf Knopfdruck angelegt.
• Preset-Dropdown: Gespeichertes Preset auswählen → füllt alle Eingabefelder automatisch
• "Neu": Setzt alle Eingabefelder zurück
• "Löschen": Entfernt das gewählte Preset
• "Als Preset speichern": Erscheint im Abhängigkeitsbaum nach erfolgreicher Analyse

Kurzgesagt: Der Verlauf merkt sich automatisch alles was analysiert wurde. Presets sind manuell gespeicherte Favoriten für wiederkehrende Abfragen. ## Traversal-Entscheidung Beim Traversal wird für jede gefundene FK-Beziehung ein Dialog mit drei Optionen angezeigt:

Traversieren:
Die abhängigen Datensätze werden geladen und ins Script aufgenommen. Standardverhalten für die meisten Beziehungen.

Überspringen:
Die Beziehung wird ignoriert – keine Datensätze dieser Tabelle im Script.

Subselect:
Die Tabelle wird nicht traversiert, aber FK-Werte im Script werden durch einen Subselect ersetzt. Ideal für Referenzdaten (z.B. Abteilungen, Statuswerte), die auf der Ziel-DB bereits existieren aber andere IDs haben.
Nach Auswahl von "Subselect" erscheint ein zweiter Dialog zur Auswahl der Lookup-Spalte(n) – diese werden im WHERE des Subselects verwendet.

Beispiel:
Statt 90 AS DEPARTMENT_ID wird im Script generiert:
(SELECT DEPARTMENT_ID FROM DEPARTMENTS WHERE DEPARTMENT_NAME = 'Executive') AS DEPARTMENT_ID

Die Entscheidungen werden beim Preset-Speichern mit gesichert und beim nächsten Laden des Presets automatisch angewendet. ## Abhängigkeitsbaum Nach der Analyse wird ein hierarchischer Baum angezeigt:

• Root-Tabelle mit dem gesuchten Datensatz
• Kind-Tabellen – alle über FK-Beziehungen abhängigen Tabellen
• Zeilenanzahl pro Tabelle in der Zusammenfassung

Von hier aus können:
• ← Zurück: Eingabe ändern
• Als Preset speichern: Aktuelle Abfrage als Preset sichern
• Merge Scripts erzeugen: Script-Generierung starten ## MERGE-Script Das generierte MERGE-Statement pro Datensatz:

MERGE INTO <tabelle> tgt
USING (SELECT ... FROM DUAL) src
ON (<pk-abgleich>)
WHEN NOT MATCHED THEN INSERT ...;

ON-Klausel:
• Normalerweise Abgleich über alle PK-Spalten
• Bei Suche über Namensspalte: Abgleich über diese Spalte (erlaubt neue PK-Generierung per Sequence)

Werte-Priorität pro Spalte:
1. PL/SQL-Variable (FK auf Sequence-gemappten Parent-PK)
2. SEQUENCE.NEXTVAL (direkte Sequence-Zuordnung)
3. Subselect (FK auf Tabelle mit Subselect-Mapping)
4. SQL-Literal (Wert aus der Quelldatenbank)

Ausgabe:
<ausgabeverzeichnis>/<TABELLENNAME>/MERGE_<TABELLENNAME>.sql
Pro Tabelle eine Datei, wird bei jeder Generierung überschrieben. ## PL/SQL-Block Wenn Sequences konfiguriert sind, wird ein PL/SQL-Block erzeugt:

DECLARE
  v_PKCOL_1 NUMBER;
BEGIN
  SELECT SEQ.NEXTVAL INTO v_PKCOL_1 FROM DUAL;
  MERGE INTO ... ;
END;
/

• Pro Sequence-PK eine Variable (v_<PKCOL>_<N>, max. 30 Zeichen)
• FK-Spalten in Kind-Tabellen erhalten automatisch die Variable statt des Literals
• Skip-Check: Bei INSERT-only mit Kind-Tabellen wird nach dem Root-MERGE SQL%ROWCOUNT geprüft – wenn nichts eingefügt wurde, wird abgebrochen ## Sequence-Mappings Tab "Sequence-Mappings" im MergeGen-Bereich.
Ordnet PK-Spalten einer Oracle-Sequence zu.

Tabelle mit drei Spalten:
• Tabelle: Tabellenname
• PK-Spalte: Primärschlüssel-Spalte
• Sequence-Name: Name der Oracle-Sequence

"Hinzufügen": Neuen Eintrag anlegen (alle drei Felder Pflicht).
"Entfernen": Markierten Eintrag löschen.

Beim Generieren werden Mappings als Vorschlag verwendet. Vierstufige Logik:
1. Store-Eintrag (bereits gespeichert)
2. STB_TABDEF-Tabelle (Spalte SEQ_NAME zur Tabelle in TAB_NAME)
3. Trigger-Erkennung (BEFORE INSERT mit NEXTVAL)
4. Leeres Feld (User-Eingabe)

Leere Eingabe = PK-Wert aus Quelle 1:1 übernehmen. ## Virtuelle FKs Tab "Virtuelle FKs" im MergeGen-Bereich.
Definiert FK-Beziehungen, die nicht als DB-Constraint existieren.

Tabelle mit vier Spalten:
• Child-Tabelle: Tabelle mit der FK-Spalte
• FK-Spalte: Spalte, die den Fremdschlüssel enthält
• Parent-Tabelle: Referenzierte Tabelle
• Parent-PK-Spalte: Referenzierte Spalte im Parent

"Hinzufügen": Neuen virtuellen FK anlegen (alle vier Felder Pflicht).
"Entfernen": Markierten Eintrag löschen.

Virtuelle FKs werden beim Traversal mit echten DB-FKs kombiniert. Auto-Bereinigung: Wenn ein virtueller FK inzwischen als echter Constraint in der DB existiert, wird er automatisch entfernt. ## Konstantentabellen Tab "Konstantentabellen" im MergeGen-Bereich.
Tabellen, die hier eingetragen sind, werden bei der Script-Generierung aus dem MERGE-Script gefiltert. Die Datensätze dieser Tabellen erscheinen zwar im Abhängigkeitsbaum, aber im generierten SQL wird kein MERGE für sie erzeugt.

Typischer Einsatz:
Stammdaten-Tabellen (z.B. Status-Codes, Länder, Währungen), die auf der Ziel-DB bereits vorhanden sind und nicht überschrieben werden sollen.

"Hinzufügen": Tabellenname eingeben (wird automatisch in Großbuchstaben umgewandelt).
"Entfernen": Markierten Eintrag löschen. ## Subselect-Mappings Persistent gespeicherte Subselect-Konfigurationen.
Werden automatisch angelegt, wenn bei der Traversal-Entscheidung "Subselect" gewählt und Lookup-Spalten ausgewählt werden.

Datei: config/mergegen/subselect-mappings.txt
Format: TABELLE|PK_SPALTE|LOOKUP_SPALTE1;LOOKUP_SPALTE2

Einmal konfigurierte Subselect-Mappings werden bei zukünftigen Generierungen automatisch angewendet, ohne erneute Abfrage. ## DB-Verbindung Im Einstellungen-Bereich unter "DB-Verbindung".

Profil: Gespeicherte Verbindungen laden/löschen.
Host / Port / SID: Oracle-Datenbankserver (Port Standard: 1521).
Benutzer / Passwort: Anmeldedaten (Passwort wird nicht gespeichert).
Schema: Zielschema (automatisch Großbuchstaben).

"Verbindung testen": Prüft die Einstellungen im Hintergrund.
"Speichern": Profil auf Festplatte speichern.

Ausgabeverzeichnis:
Zielordner für die generierten SQL-Dateien. Über "Durchsuchen" wählbar, wird sofort in app.properties gespeichert.
